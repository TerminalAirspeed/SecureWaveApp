# Reporting SecureWave security vulnerabilities (DRAFT)

Please use **private GitHub vulnerability reporting** after the repository maintainer enables the feature in Settings → Security. Report crypto, key-management, pairing, replay, file-at-rest, Android component, permission, expiration, and radio protocol issues privately.

Do not submit private keys, pairing secrets, contact lists, real messages, or identifying logs through public GitHub Issues. Use synthetic reproductions and include the affected version/code, Android version, expected/observed behavior, severity, and reproduction steps.

**Supported versions:** The currently published signed beta only; old lab ciphertext formats are not supported. SecureWave beta is not independently security-audited, and no response SLA is promised.

If private vulnerability reporting is unavailable, contact the owner through a mutually agreed private channel before sending exploit details. **Owner must enable private vulnerability reporting and review before publication.**
